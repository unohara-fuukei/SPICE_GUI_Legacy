# SPICE Native Android App (Kotlin + Jetpack Compose + Material 3)

Fully native rendering, zero WebView. This is the Kotlin implementation on the `native` branch; an earlier Rust + egui exploration is preserved in [`../NATIVE_PORT.md`](../NATIVE_PORT.md).

> **Not the original.** This app is an unofficial port of the original SPICE GUI desktop application ([SPICE-Protein/SPICE_GUI](https://github.com/SPICE-Protein/SPICE_GUI), by [redelectricity](https://www.biostars.org/u/158838/)). For real work, use the original. See the repository root [README](../README.md) for the full disclaimer, credits, and an honest list of current differences.

## Build

```bash
export JAVA_HOME=<jdk17>
export ANDROID_HOME=<android-sdk>
./gradlew :app:assembleRelease
# output: app/build/outputs/apk/release/app-release.apk
```

- `applicationId com.spice.nativeapp`, `minSdk 24`, `targetSdk 29`
- Release signing injected via `SPICE_KS / SPICE_KSPASS / SPICE_ALIAS`
- Since v0.5.0 the ONNX Runtime for Android native libs are bundled (arm64-v8a / armeabi-v7a); model weights are downloaded from HuggingFace on first use, not packaged in the APK
- Under a TLS-intercepting proxy, the Gradle JVM needs a custom truststore
- AGP 9 requires `android.builtInKotlin=false`

## Known gaps

1. **ONNX weight inference**: resolved since the earlier "classical CV substitute" note — the gel-photo segmentation now runs the original's GelGenie U-Net via onnxruntime-android with weights downloaded on demand (same runtime-download behavior as the original), with the pure-Kotlin classical-CV path kept as the offline fallback; protein fold inference (1.7.10) is real ONNX when a model file is present, heuristic otherwise.
2. **DNA viewer part/feature tracks**: implemented (1.7.17) — the sequence rows now render the original's per-row feature tracks (SnapGene-style blue labels, arrow/box/promoter shapes with strand mirroring, tap-to-lock feature tooltip) and parts tracks (`PART_COLOR #ac68cc`, always-on, no interaction), with the original's greedy interval stacking and row-height reservation semantics (`calculateRowYOffsets`/`getAnnotationLabelHeight`/`getAnnotationStackHeight`). Demo data carries the original's three OVE parts (`pj5_00001` / `Part 0` / `Curtis' Part`, 1-based). Minor disclosed divergence: the feature tooltip anchors inside the tapped row (the original pins it in the editor viewport and it stays put while scrolling), and there is no hover highlight (touch has no hover; the original's hoveredId path is not reachable on Android).
3. **AI agent tooling**: streaming, cross-session history, the bounded agent loop (max 6 steps), 15 of 16 built-in tools (workspace context, ddG prediction, DNA analysis, primers, codon usage, ORFs incl. circular wrap, revcomp, Tm, document search, memory recall, apply-DNA/protein, import-mutations, remember-fact) and the approval gate + memory + audit panels are ported. Platform differences, disclosed: **MCP servers** (stdio local command processes spawned via Tauri in the original) cannot run inside the Android sandbox, so the MCP registry/settings panel is not shipped; the original client (`ai/mcp.ts` + `src-tauri/src/mcp.rs) is a stdio-only local-subprocess protocol with no HTTP/SSE/remote-transport branch to port, and adding a remote MCP transport would be a new feature rather than a 1:1 replica, so it stays out of scope; **`figure_add_chart`** is now wired to the Figure Studio chart layer (1.7.19, `core/FigureCharts.kt` ports `charts.ts`/`figureAgent.ts`/the chart parts of `types.ts`; `tools/FigureScreen.kt` renders chart nodes and registers the command handler) — when no editor screen is mounted it fails with the original's "Open Figure Studio…" message, exactly as the original does unmounted.
4. **i18n**: fully implemented (1.7.19) — all UI strings are wired through the runtime (`I18n.t()/tf()`); the dictionary system mirrors the original's Paraglide-JS stack: `assets/i18n/core/<lang>.json` carries the main dictionaries verbatim (project.inlang messages + the 8 tool `messages.json`, 3921 entries × 6 languages en/ja/ko/de/nl/sv, zh is the source language and returns as-is), `assets/i18n/extras/<lang>.json` carries the Android-branch-only copy (1050 keys × 6, hand-translated; the original has no corresponding strings to copy). Lookups are keyed on the zh source text exactly as in the original's tool pages; any string not in either dictionary falls back to the Chinese source text (the original's compile-time message function semantics translate to a runtime map here).
5. **SPD publishing**: implemented (v1.7.16) — settings-page proxy/token, gene & vector library sheets, protein-page fold publish chain (protein→sequence→environment→model→fold) with SHA-256 dedup caching, and exact-match fold query via the `/query` graph DSL. Divergence from the original: the original's desktop-only gate (`isTauri`) is intentionally lifted on Android; when a model checkpoint file is present the fold's `checkpointSha256` is the real streamed SHA-256 of that file (1 MiB read buffer, mirroring the main `model_sha256` digest), and only when no ONNX model file is present (or hashing fails) is it submitted as `sha256:` + 64 zeros (placeholder, disclosed here) instead of a real file digest.
6. **Presenter slideshow**: implemented (1.7.17) — full-screen presenter mode over project documents, parsing the original's slide syntax 1:1 (`---`/H1/H2 page breaks, H3 sub-headers, nested & task lists, aligned tables, fenced code, `>` blockquotes as speaker notes, footnotes `[^id]` + inline `[^free text]` with cross-block numbering, sup/sub `^2^`/`~x~` incl. parenthesized `^(a+b)^`, ==highlight==/~~strike~~, reference links `[text][id]`, leading-`//` comments), with the original's iA-Presenter look (narrative color stops, black-weight glow titles, tap-to-advance, 3px progress bar, speaker sidebar with timer/counter/next-slide preview/notes) and zh.json strings verbatim. Divergences from the original, disclosed: page navigation and notes-toggle are on-screen buttons instead of the `←→/P/F/Esc` keyboard shortcuts (Android has no hardware keyboard by default), the `F` fullscreen shortcut is omitted (the dialog is already fullscreen), and remote (`http(s)://`) slide images render a placeholder box with alt text instead of loading — no network image layer is shipped; local paths load via BitmapFactory as in the original's `file://` handling.
